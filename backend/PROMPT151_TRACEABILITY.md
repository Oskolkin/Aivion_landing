## Production defects fixed in this pass

1. **Export** generated bytes and a random UUID URL without storing the file; provenance used `_ = InsertExportProvenance`. Now: generate → `ArtifactStore.Put` (S3 in API, memory in tests) → `chat_attachments` (id, seller, session, message, filename, mime, size, storage_key, sha256) → `chat_export_provenance.attachment_id` → download URL. Storage or provenance failure → turn `EXPORT_FAILED`, no download URL. Handler download tries Chat v2 store first.
2. **Category N+1**: `get_category_contexts` called `GetCategory` per id. Now `factualapi.BatchGetCategories` (set `ANY($3)` SQL) and Chat tool uses it only.
3. **Entity memory** owner is persisted `referenced_entities_json` / `EntityRef` (kind, canonical id, label), loaded on the next turn. SKU-text tokenizer remains a hint only. Ambiguous “по нему” with multiple SKUs asks clarification.
4. **OpenAI strict schemas**: every property is `required`; optional fields use `["T","null"]` unions. Local conformance test lists all catalog tools. `LIVE_PROVIDER_SMOKE = NOT RUN` because `OPENAI_API_KEY` is empty.
5. **Action 4→3 / singleton**: tests no longer `t.Skip`; they seed Prompt14 group fixture / ungrouped case. Handoff deletes the session if binding insert fails.
6. **P1/P2 stock 0→300**: tests bind Polaroid analog SKU-B1 (`ozon_sku=9105`, relabeled Polaris 417), freeze Turn1, promote STOCK snapshot to 300, run P2, assert tool `sellable_stock` values.
7. **Mixed grounding**: ATTACHMENT **and** FACT/PUBLICATION required; cabinet tools must execute; attachments do not disable the catalog.
8. **Streaming**: seller-visible text deltas only after Agent validation; status events allowed first.
9. **Unknown-response retry**: completed idempotency payload replay; counts and provider generations must not increase.
10. **Required/optional factual failure**: sales down → limitation, no guessed seller number; ads down with sales+stock remaining → answer + limitation / LIMITED, not automatic FAILED.
