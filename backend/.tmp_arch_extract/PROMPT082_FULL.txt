0. PURPOSE
==================================================

Prompt №8.1 реализовал:

- RESOLVE_CONTEXT;
- SEAL_UNIVERSE;
- Factual Universe;
- SEALED_UNIVERSE;
- source/capability/DQ/entity-set freeze;
- immutability/integrity;
- analysis runtime;
- Worker/Asynq wiring.

Prompt №9/9.1 затем строит:

SEALED_UNIVERSE
→ Landscape
→ Materiality
→ Detail.

Независимый source-level аудит
актуального repository обнаружил
несколько оставшихся фундаментальных defects
в Prompt №8 layer.

Prompt №8.2 должен исправить их
БЕЗ переделки уже корректной части runtime
и БЕЗ реализации новых analytical features.

Основные дефекты:

1. несколько fact families одного Domain
   схлопываются в FactualReadContext
   до одной DomainBinding;

2. domain_watermarks являются mutable projection
   без исторических revisions,
   поэтому состояние AS KNOWN AT cutoff
   может исчезнуть до RESOLVE_CONTEXT;

3. source contract provenance
   freeze-ится неточно / частично synthetic;

4. fact-family ↔ capability matching
   использует prefix heuristic;

5. DQ resolver работает fail-open
   при реальных PostgreSQL errors;

6. Universe entity-set computation
   напрямую читает canonical business tables
   из analysis layer;

7. Category/entity-set hashes
   используют internal DB IDs;

8. SEALED binding не всегда сохраняет
   source/watermark semantics 1:1;

9. production token signer использует
   hard-coded HMAC secret;

10. существующий Factual API boundary gate
    не ловит direct canonical SQL
    из internal/analysis.

После Prompt №8.2 должно быть доказано:

Captured Analysis Cutoff
        ↓
historical source/readiness revisions
        ↓
RESOLVE_CONTEXT
        ↓
exact fact-family bindings
        ↓
SEAL_UNIVERSE
        ↓
immutable semantic Universe
        ↓
SEALED FactualReadContext
        ↓
exact same fact-family/capability/DQ/entity reality

и поздний ingestion/readiness update
не может изменить или стереть эту reality.
